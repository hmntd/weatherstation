# WeatherStation API

## 1. Аналіз предметної області
**Предметна область:** Інформаційна система для агрегації, збереження та моніторингу метеорологічних даних (RESTful Web API).

**Опис предметної області:**
Сучасні користувачі потребують швидкого доступу не лише до поточного прогнозу погоди, а й до історії погодних умов (температура, вологість, швидкість вітру) у різних локаціях. Цей проєкт являє собою бекенд-застосунок (API), який виступає посередником між клієнтом та зовнішнім постачальником метеоданих (Open Meteo).

Замість того, щоб щоразу робити повільні запити до зовнішніх сервісів, наша система синхронізує дані та акумулює їх у власній реляційній базі даних (MySQL). Це дозволяє швидко віддавати історичні зрізи погоди для обраних міст. Система є багатокористувацькою: вона передбачає безпечну автентифікацію (JWT) та дозволяє користувачам керувати власними списками міст для відстеження. Архітектура побудована за принципами N-Layer/Clean Architecture, що забезпечує чітке розділення доступу до даних, бізнес-логіки та веб-шару.

## 2. Основні функції системи

Нижче наведено 5 ключових функцій, які реалізовані у даній предметній області:

1. **Безпечна реєстрація та авторизація користувачів (JWT Authentication)**
   Система дозволяє користувачам створювати акаунти. Паролі не зберігаються у відкритому вигляді (використовується надійне хешування через алгоритм BCrypt). Після успішного входу користувач отримує JWT (JSON Web Token), який використовується для безпечного доступу до захищених маршрутів API.

2. **Управління географічними локаціями (CRUD операції для Міст)**
   Можливість додавати нові міста до системи, вказуючи їхні точні географічні координати (широту та довготу). Також підтримується отримання списку всіх доступних міст, їх редагування та видалення з бази даних.

3. **Синхронізація метеоданих із зовнішнім API (Open Meteo Integration)**
   Реалізовано механізм отримання реальних погодних даних від стороннього провайдера. Система формує HTTP-запити на основі координат обраного міста, парсить отриманий JSON-відгук і фільтрує дані (наприклад, зберігаючи лише кожну третю годину для оптимізації).

4. **Акумуляція та оптимізація історії погоди**
   Отримані з API дані (температура, вологість, швидкість вітру та час) автоматично конвертуються у внутрішні сутності та зберігаються в базу даних MySQL. При цьому система вміє "самоочищуватися": перед записом нових даних застарілі прогнози для конкретного міста автоматично видаляються, щоб запобігти переповненню бази. Клієнт може миттєво отримувати історію погоди з локальної БД.

5. **Персоналізація моніторингу (Прив'язка користувачів до міст)**
   Завдяки зв'язку "Багато-до-багатьох" (Many-to-Many), авторизований користувач може формувати власний список міст, додаючи їх до своїх "улюблених". Це дозволяє налаштувати персоналізовану видачу погоди лише для тих локацій, які цікавлять конкретного юзера.
